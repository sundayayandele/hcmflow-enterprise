# Employee payslip portal

Open **Payslips** in the demo navigation. Select a synthetic employee, view a released month and download its PDF. Scheduled months hide financial details. **Simulate payment day** advances only the demo viewing date; **Reset to today** restores the Lagos date. Sample salary day defaults to 25 for illustration and clamps to the last day of shorter months. Approved payroll retains its original dates. Demo data resets on refresh.

In staging, independently approving a simulation automatically saves an encrypted payslip per employee in the payroll database, in the same transaction as approval. Records preserve the approved calendar, financial lines and checksum. Release is evaluated at request time from 00:00 Africa/Lagos on the configured payment date, so no scheduler is required. Availability does not certify payment by a bank. Run approval does not enable production finalization.

`GET /api/payroll/payslips` lists only the signed-in employee's archive; scheduled entries contain metadata only. `GET /api/payroll/payslips/{id}` checks tenant, signed employee identity and payment date before decrypting the document and recording an audit event. There is no employee/date override in the live UI or API. Privileged payroll operators retain approved register exports for review; personal archive access still requires a linked employee identity. Employee CSV exports also enforce the release date. PDFs are generated locally from an authorized document and marked SIMULATION — NOT FOR PAYMENT.

For existing staging installations, back up first, preserve the existing PII_KEY and run the documented schema migration before restarting payroll with the updated Compose environment. The migration adds `payslip_archives` with tenant FORCE RLS; payroll now also receives PII_KEY. Restore this key alongside the database when recovering archives. An independent approver can idempotently archive an older approved simulation using `POST /api/payroll/runs/{id}/payslips`; its maker cannot perform this backfill. Provision employee accounts with `--employee-id` and issue a fresh login token after linking.

The public GitHub Pages demo contains synthetic data only. Real employee records require the authenticated staging backend and database. Production Nigerian statutory validation, specialist review and finalization remain outstanding. Future work includes controlled correction/reissue, retention policies and notifications; an archived slip cannot currently be edited through the API.

The payslip view and downloaded PDF identify the employer by company name and show the employee name, salary bank/account details when archived, and a bordered table of salary components, deductions, gross, reimbursements and net pay. Public demo accounts use clearly fictional identifiers. Legacy archives without bank details explicitly show that they were not provided; the UI does not infer a bank account or certify a transfer.
